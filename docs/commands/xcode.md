# xcodebuild and simctl

The native layer is built and tested from the command line through small scripts in `ios/scripts/` that wrap `xcodebuild` and `xcrun simctl`. They need Xcode 26 or newer and an iOS Simulator runtime, and **no signing identity or team**.

## The scripts (run from `ios/`)

| Command | What it runs |
|---|---|
| `sh scripts/simulator.sh` | Prints the UDID of `$IOS_SIMULATOR` (name or UDID) or the first available iPhone. Creates, boots and changes nothing. |
| `sh scripts/test.sh` | `app` then `package` |
| `sh scripts/test.sh app` | `xcodebuild test -project App.xcodeproj -scheme App` on the simulator: **hosted** tests (Keychain, build configuration, wiring) |
| `sh scripts/test.sh package` | `xcodebuild test -scheme AppCore-Package` in `Packages/AppCore` on the simulator |
| `sh scripts/test.sh direct` | `build-for-testing`, then runs the package's `.xctest` bundle with the simulator's own `xctest` via `simctl spawn`, bypassing xcodebuild's test-runner handshake |
| `sh scripts/check-release-config.sh` | Builds **Release** for the simulator SDK unsigned and asserts the built `Info.plist` has `APIScheme=https` and **no** `NSAppTransportSecurity` key |
| `sh scripts/check-static.sh` | Greps sources for ATS opt-outs, trust overrides, logged tokens, credentials in UserDefaults or files, hard-coded http URLs, secrets, committed team IDs, server credentials |

Build products and logs go to `ios/.derived-data/` (ignored); `check-release-config.sh` writes its build log to `ios/.derived-data/release.log` and, on failure, prints its last 30 lines and names it. Running any of these scripts leaves no Git-visible file. (Native v0.1.0 wrote the log to an un-ignored `ios/.derived-data-release.log`; see [troubleshooting](../troubleshooting/git-copier-ci.md#upgrade-refused-after-running-the-ios-checks).)

## xcodebuild

```bash
xcodebuild -version
xcodebuild -list -project ios/App.xcodeproj
xcodebuild test -project App.xcodeproj -scheme App -destination "id=$(sh scripts/simulator.sh)" \
  -derivedDataPath .derived-data/app -onlyUsePackageVersionsFromResolvedFile
xcodebuild build -project App.xcodeproj -scheme App -configuration Release \
  -destination "id=$UDID" CODE_SIGNING_ALLOWED=NO
sudo xcodebuild -runFirstLaunch        # install system components after installing/updating Xcode
sudo xcode-select -s /Applications/Xcode.app
xcode-select -p
```

| Option | Why the scripts use it |
|---|---|
| `-destination "id=UDID"` | One exact simulator, never "any". |
| `-derivedDataPath` | Isolated, project-local build products. |
| `-onlyUsePackageVersionsFromResolvedFile` | Never resolve a package version other than the committed one. |
| `CODE_SIGNING_ALLOWED=NO` | Release check needs no identity. |

The Xcode project itself is static and generated by `native-ios-template/tools/gen_pbxproj.py`; settings live in `ios/Config/*.xcconfig`, not in the project file. The `App` folder is an Xcode *synchronized folder*: a new Swift file in it is in the target automatically.

## xcrun simctl

```bash
xcrun simctl list runtimes                  # installed iOS runtimes
xcrun simctl list devices available         # devices you can boot
xcrun simctl boot <UDID>
xcrun simctl bootstatus <UDID> -b           # wait until booted
xcrun simctl shutdown <UDID>                # or: all
xcrun simctl erase <UDID>                   # destructive: wipes that simulator's data, including its Keychain
xcrun simctl create "iPhone Test" "iPhone 17" <runtime-identifier>
xcrun simctl spawn <UDID> log stream --level debug
xcrun simctl runtime list                   # runtime images (download/manage)
```

## swift test (host)

```bash
cd ios/Packages/AppCore && swift test
```

Runs the 58 package tests on macOS: no simulator. The Keychain tests are deliberately **not** in this target; see [why](../ios/testing.md#why-the-keychain-tests-must-be-hosted).

## The end-to-end scenario

```bash
node ios/scripts/e2e.mjs [--rebuild] [--down]     # from anywhere; uses the project's own commands
```

Runs `db:init`, `db:up`, `db:migrate`, `build`; starts `next start` on a free loopback port with open sign-up; creates two accounts; runs phase one of `ios/AppTests/EndToEndTests.swift`; restarts the web server **and** the database; runs phase two; checks the server log holds no token. `--rebuild` forces a fresh web build, `--down` stops the database afterwards. Needs Docker, Node 26 and a simulator at once. Prints `END-TO-END SCENARIO PASSED` on success.
